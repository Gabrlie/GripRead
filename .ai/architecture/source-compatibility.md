# 书源兼容性设计

本文档定义网络小说阅读书源的输入、执行边界和兼容性状态。网络小说产品流程见
[产品需求](../product/requirements.md)，运行时模块见[架构总览](overview.md)，固定 fixture 与验收场景见
[工程测试与验收](../engineering/testing.md)。RSS 订阅是独立模块，不使用本文件的书源规则。

## 书源输入与保留

用户可以通过文件、链接或粘贴导入书源 JSON。系统保留用户导入的原始内容，另存解析后的元数据和验证结果；原始内容用于重新验证、查看兼容报告和排查差异。书源登录态、凭据和本地路径属于设备数据，不随书源配置上传或备份。

导入内容进入以下状态之一：

- **已导入**：原始配置已保存，尚未完成验证。
- **未验证**：配置结构已保存，但尚未运行所需能力检查。
- **验证通过**：目标能力在当前运行时和测试请求中可用。
- **存在不支持能力**：配置可保存，但至少一个依赖超出首发边界，报告中列出具体能力。

状态不能用一个模糊的“可用”替代。搜索、详情、目录或正文单项失败时，报告要指明失败阶段、原因和是否影响其他能力。

## 统一适配器能力

每个书源通过 `SourceAdapter` 对外提供异步任务：

- 按关键词搜索书籍；
- 获取书籍详情；
- 获取章节目录；
- 获取章节正文；
- 返回验证和兼容性报告。

搜索结果按书源分组并逐步返回，单源失败不应丢弃其他源结果。正文和目录结果进入统一网络章节模型，供阅读核心使用；下载和缓存由 Rust 网络/文件层持久化，前端通过异步任务订阅进度。

## 支持范围

首发优先兼容常用文本书源中的以下能力：

- 常用 CSS/Jsoup 选择与清理；
- XPath、JSONPath 和正则表达式；
- 变量替换、分页和请求参数；
- 纯 JavaScript 规则；
- 有限网络请求和缓存方法。

Java 类调用、Android 专属桥和复杂 WebView 登录不列入首发保证。依赖这些能力的书源仍可保留原始配置并显示不支持原因，不伪装为验证通过。

## JavaScript 执行边界

书源 JavaScript 通过 `rquickjs` 嵌入 QuickJS-NG，在独立工作线程执行。它不具备 UI IPC、任意文件访问或直接修改 SQLite 的能力。宿主桥只暴露有限的网络和规则方法，并保留常用书源需要的 HTTP 同步语义；这里的“同步 HTTP”是脚本调用语义，不是 GripRead 的 WebDAV 数据同步。前端以异步任务调用书源执行，避免脚本阻塞 UI。

每次执行受时间、内存和网络请求超时约束。脚本越界、超时、返回格式错误或请求失败时，适配器生成失败阶段和兼容性报告，释放任务资源，不让异常污染书架、阅读位置或 RSS 数据。

## 书籍身份、换源与章节定位

跨来源换源保留同一 `Book` 持久身份，但不把新来源章节直接按身份当作旧章节。系统根据新旧目录和文本上下文映射章节，匹配不准时返回最接近的候选和原因，由用户确认后更新 `ReaderLocator`。具体映射算法不在本文件规定。

章节正文有网络持久资源标识，书源更新时优先用目录和文本上下文确定资源对应关系；无法确定时保留旧位置和新候选，不能静默跳转。换源后的章节缓存按资产和内容哈希管理，重复内容去重但不覆盖用户已选位置。

## 验证与报告

验证至少覆盖搜索、详情、目录和正文链路，并在每个阶段记录请求或规则失败原因。报告区分：

- 配置是否已保存；
- 运行时是否支持所需规则；
- 网络请求是否成功；
- 结果是否符合统一模型；
- 哪些能力仍可用、哪些能力明确不支持。

固定书源 fixture 用于验证从搜索到正文的完整链路，并包含至少一个触发明确 `unsupported` 的规则。三端运行时要分别实测 QuickJS-NG 通过 `rquickjs` 的集成、网络超时和内容清理；不能因为某平台可构建就宣称其他平台天然兼容。

## 内容清理与缓存边界

书源返回的 HTML 先经过内容清理，再交给阅读核心；正文资源可离线缓存到本机。缓存不进入 WebDAV 自动同步和备份，用户只能明确执行书库文件上传/下载。RSS HTML 使用独立的 RSS 清理路径，不把 RSS 文章当作书源章节。

兼容性状态、脚本限制和固定 fixture 的验证要求还需与[路线图](../plans/roadmap.md)及[工程测试与验收](../engineering/testing.md)保持一致。
