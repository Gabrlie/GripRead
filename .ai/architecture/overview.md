## 技术栈与运行边界

GripRead 使用 Tauri 2 构建三端桌面与移动壳层，前端采用 React、TypeScript、Vite、Tailwind 和 shadcn/ui。React 只负责界面状态、布局和用户交互；Rust 负责 SQLite、本地文件、网络请求、内容解析、同步队列和平台文件能力。

前端通过 Tauri 命令和事件调用 Rust 能力。耗时工作（书源搜索、章节下载、RSS 刷新、同步和导入）以异步任务返回状态事件，不在 UI 线程上执行。Rust 负责把任务结果持久化后再通知前端，因而界面重启可从 SQLite 恢复任务状态和本地内容索引。

SQLite 是本地结构化数据的唯一持久入口；TXT/EPUB、章节正文、RSS 文章正文、图片和字体文件按本地文件策略保存，并在数据库中保存元数据、哈希和可用性。网络正文缓存与 RSS 内容缓存属于设备本地数据，不进入同步和备份。

## 模块边界

### 阅读核心

阅读核心将 TXT、无 DRM 流式 EPUB 和网络章节转换为统一的章节/资源序列。Rust 负责解析、文本规范化、目录、搜索、资源持久化和 `ReaderLocator` 数据；前端阅读模块负责依赖 WebView 实际字体和视口的排版分页，以及仿真、平移和无动画等翻页动画。两侧共享 `ReaderLocator` 语义，分页、定位和动画保持分离：StPageFlip 只能接收前端已经分页的内容，不能承担内容解析或位置判断。

前端阅读模块还提供分页模式和滚动模式等显示状态，但不掌管书架、书源或同步。重新分页时按章节资源、文本偏移和上下文恢复位置，不保存或依赖页码。

### 书源模块

书源模块负责原始规则保存、导入、验证、兼容性报告，以及搜索、书籍详情、目录和正文适配。适配器执行在 Rust 管理的独立脚本工作线程中，并通过受限宿主桥访问网络和必要的规则能力；前端只消费异步任务结果。详细支持矩阵见[书源兼容性](source-compatibility.md)。

### RSS 模块

RSS 模块独立解析 RSS 和 Atom，处理 OPML 导入导出、订阅分组、刷新、去重、文章列表、未读、收藏和文章正文。它不调用网络小说书源适配器，也不把 Legado `rssSource` 网页规则当作 RSS 输入。RSS HTML 与全文提取结果先清理，再交给文章阅读视图；图片只进入本机缓存。

### 数据同步层

同步层包含 `SyncService`、`SyncStatus` 和持久同步队列，负责 WebDAV 连接、状态文件、版本与删除标记、因果顺序、冲突记录、重试和状态事件。同步层不读取阅读器页码，也不上传正文缓存、RSS 内容缓存、凭据、书源登录态或本地路径。协议和恢复行为见[同步设计](sync.md)。

### 本地存储与文件层

文件层负责导入 TXT/EPUB、云端书库文件上传和下载、缓存、哈希去重和本地路径。`Book` 代表跨文件的书籍身份与用户状态；`BookAsset` 代表本地文件、云端文件或网络章节资源。身份与资产分离后，可以在同一书架记录下关联本地文件、下载云端文件或更换网络来源。

## 核心模型

下列模型是模块交界处的稳定语义，字段的具体数据库类型在实现阶段确定：

| 模型 | 责任 | 关键关系 |
| --- | --- | --- |
| `Book` | 书籍身份、标题、来源关系、分组与阅读状态 | 可关联多个 `BookAsset` |
| `BookAsset` | TXT/EPUB 文件、云端文件或网络章节资源 | 记录位置、内容哈希和本机可用性 |
| `ReaderLocator` | 当前章节/资源、文本偏移和上下文 | 跨分页、设备和换源恢复位置 |
| `SourceAdapter` | 搜索、详情、目录、正文和兼容报告 | 对一个导入书源提供异步能力 |
| `FeedService` | RSS/Atom 订阅、OPML、刷新和文章状态 | 与书源模块保持独立 |
| `SyncService` | WebDAV 同步、重试、冲突和状态事件 | 读写同步队列与远端状态文件 |
| `SyncStatus` | 当前连接、队列、重试和错误状态 | UI 只订阅状态，不直接控制协议 |

网络小说换源保留 `Book` 的持久身份，但新来源的章节不能直接按身份视为同一章；适配层根据新旧目录和文本上下文映射章节，并在匹配不准确时返回最接近候选及其可解释原因，由 UI 请求用户确认。不静默覆盖已有位置。

本地内容用哈希去重，重复导入不应产生多个相同资产。书架删除只删除同步的书架记录，不删除云端书库文件；本机缓存清理仅清理本地数据。

## 书源脚本安全边界

书源 JavaScript 通过 rquickjs 嵌入 QuickJS-NG，运行于独立工作线程，不直接拥有 UI IPC 或任意文件访问。宿主桥只暴露有限、可审计的网络和规则能力，保留书源需要的 HTTP 同步语义，并对脚本执行时间、内存和网络请求设置超时。复杂 WebView 登录、Android 桥和 Java 类不作为首发保证能力。

脚本结果进入统一适配器后再写入数据库；超时、越界或格式错误转为书源兼容性报告和任务失败状态，不让脚本异常破坏 UI 或阅读位置。

## 内容安全与清理

EPUB 文本和 RSS HTML 在进入阅读器前清理危险或不可用的 HTML 结构，保留正文、标题、链接和图片引用所需信息。图片下载、缓存和失败状态由本机资源层管理。网络内容只通过 Rust 网络边界获取，前端不直接承担书源脚本或 WebDAV 凭据。

## 运行时事件方向

用户动作从 UI 进入异步任务；任务将阶段、结果或错误写入 SQLite/文件层，再由 Rust 发送状态事件。阅读器可先读取本地内容后订阅下载或同步事件；事件到达不会强制改变当前阅读位置。同步故障只更新 `SyncStatus`，不阻断阅读核心的本地调用。

## 平台与交付约束

首发目标为 Android、Windows 和 macOS。QuickJS 运行时、SQLite、文件能力、网络和 StPageFlip 的三端构建与行为必须在目标平台实测；不能仅凭运行时名或桌面兼容性宣称 Android、Windows、macOS 天然兼容。实施分阶段和验证门槛见[路线图](../plans/roadmap.md)，验证场景见[工程测试与验收](../engineering/testing.md)。
