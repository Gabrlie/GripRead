# Stage 6: Self-hosted server

Status: in-progress

## Outcome

One reader runs `gripread-server` from a published image and reads in a browser with the same library, sources, and settings as the app; their devices later sync with it natively instead of through WebDAV, and it takes over long-running work. Behavior belongs to [Server](../subsystems/server.md), with sync rules in [Sync](../subsystems/sync.md) and feeds in [RSS](../subsystems/rss.md).

## Scope

Phases, each committed separately:

- P0, shared core: the workspace splits into `crates/core` and the app shell, with one command dispatcher ([decision](../notes/implemented/2026-10-13-shared-core.md)).
- P1, server and web version: `crates/server` with the account, the command API, events, uploads and exports, the built page, the web transport and sign-in in the page, the image, and its publishing workflow.
- P2, native sync: a change journal in the core, push and pull with the server as the canonical replica, automatic upload of local book files, and WebDAV suspended while connected. Planned in its own round.
- P3, server jobs: scheduled 更新目录 and the RSS module with server-side polling. Planned later.

Single user. Reaching sources from the server's location is the reader's choice of sources and outside this task.

## Interfaces

P0 adds `gripread_core::api::{dispatch, COMMANDS, Events, Reply}`, `platform::Platform`, and `AppState::open`; the app's commands become one `rpc` command. P1 adds the server's HTTP API (see the subsystem) and `src/services/{transport,files,server}.ts`.

## Acceptance criteria

- P0: the app behaves as before on Android and desktop; every command the page calls is answered by the core.
- P1: the subsystem's acceptance cases, through a headless browser against the server.
- P2 and P3: their own planning rounds add their criteria.

## Verification

P0: `pnpm check`, Android clippy, and an APK build; a core test runs commands by name and checks the page's command names. P1: server tests for the account, sessions, refused paths, upload then import, exports, and static serving; frontend tests for the web transport and sign-in; a headless Chromium run against a locally started server (first-run password, TXT upload and import, reading and turning a page, a second browser signing in to the same shelf), all passing. The image build itself could not run on this host (no Docker access); its steps were run directly (`pnpm build`, `cargo build --release --locked -p gripread-server`).

## Handoff

P0, P1, and P2 are implemented. P2 verification: Rust tests for two devices and a server library converging (renames, groups, positions, concurrent bookmark edits, exclusions both ways, removals, books arriving after their records, online books), the server's push, pull, files, and logged web edits over HTTP, and a device client against a running server picking up a web edit through the long poll; a frontend test for 服务器同步. Device acceptance with phone, web version, and PC is pending. Since 0.2.0 the `Build` workflow builds and publishes images and APKs from `dev` and `main` (pre-releases and releases). The stutter across chapter edges reported on `428e4be` is fixed (layout during chapter-edge turns back to its earlier cost). Next: P3, server jobs and RSS, with its own plan.
