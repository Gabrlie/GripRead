# 0.3.1: Comics

Status: in-progress

## Outcome

Release 0.3.1 with comic reading:
- **Online comics:** Legado image sources (`bookSourceType` 2) import, search, discover, shelve, cache, and sync like text sources.
- **Local comics:** CBZ and ZIP archives, image folders, and image-only fixed-layout EPUBs import as comic books.
- **Comic reader:** a vertical strip, single pages left to right or right to left, and double pages on wide screens, with zoom and its own settings.

The round also fixes the cloud progress prompt that returned after being dismissed, keeps online books' source titles from being replaced by generated ones, and adds a roadmap section to the READMEs.

## Scope

**Included:**
- image sources and per-page comic chapters, fetched through the source;
- local comic import and its library asset;
- the comic reader, its settings, and progress as chapter and page;
- search scope by kind, shelf marks, sync, and the web version.

**Excluded:**
- CBR (RAR) archives;
- audio and file sources;
- translating, purifying, or converting comics to local books.

## Interfaces

**Batches:**
1. the version raise;
2. the cloud progress prompt;
3. online chapter titles and converted books' contents;
4. the README roadmap;
5. image sources and comic pages (schema 26);
6. local comic import;
7. the comic reader and settings;
8. search, shelf, sync, and the web version.

## Acceptance criteria

- **Prompt:** a dismissed cloud progress prompt does not return for the same remote position.
- **Titles:** a synced or refreshed online contents list keeps the source's chapter names; a converted book keeps them too.
- **Comics:** a test image source is searched, opened, read page by page, and cached; a CBZ, a folder, and a fixed-layout EPUB import with naturally sorted pages; progress restores to the same chapter and page.

## Verification

Commands and results are recorded here per batch.

**Cloud progress prompt:** a dismissed prompt with fetches queued behind it stays dismissed (reader test), queued fetches share one, and the same device reading nearby is not asked again while reading far on is (core test against the WebDAV stub).

**Online chapter titles:** the server's own log held contents updates whose titles were all `#N`: a source that names chapters only for a signed-in reader falls back to `'#' + order`, and the server has no sign-in. Core tests cover keeping known names over placeholders from the source and from sync, fetching placeholder-only contents again once, and a converted book keeping its source contents (also in backups); a contents test covers the hidden rule items.
