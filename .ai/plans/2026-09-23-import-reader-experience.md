# Silent TXT import and immersive reading

Status: in-progress

## Outcome

Make local TXT import a background operation after file selection, shorten the time until a book is readable, and use the available reading viewport with the requested toolbar arrangement. Deliver working directory rules and automatic page turning. Behavior belongs to [Library](../subsystems/library.md), [Reader](../subsystems/reader.md), and [interaction design](../design/interaction.md); update those owners with each implementation slice.

This task intentionally changes the reader geometry and controls preserved by the previous visual baseline. Fullscreen means filling the application viewport, with safe-area handling and compact reading insets; it does not require entering the operating system's fullscreen mode. Keep the paper themes and existing typography as the starting point. Update the interaction specification's no-obscuring constraint to permit temporary toolbar overlays while preserving its no-repagination requirement.

## Scope

Cover single-file TXT import, its notifications and performance, reader viewport geometry, toolbar organization, per-book directory rules, the existing encoding workflow, and automatic turning in the currently supported paginated modes. Keep the current whole-book progress slider and previous/next-page controls in a separate progress row above the four bottom actions. Chapter-relative progress is not required for this task.

EPUB, batch import, new scrolling or double-page modes, online sources, RSS, WebDAV, AIGC, reading statistics, elaborate font effects, and custom image backgrounds remain outside this task. The pending macOS source-picker evidence from [the prior task](2026-09-19-local-library-closeout.md) remains outstanding; this task does not establish completion of all M0/M1 or Android/Windows acceptance.

### Pre-change inspection findings

- [ImportModal](../../src/components/Bookshelf/ImportModal.tsx) automatically opens a dialog for import activity/errors. Its corner button remains while a job/error exists; closing the dialog does not dismiss that button. [LibraryStore](../../src/application/library.ts) retains terminal job state without a separate notification lifetime.
- [TXT decoding](../../crates/core/src/txt.rs) detects encoding, removes an encoding BOM, and normalizes CRLF/CR to LF. This is representation conversion, not rewriting prose, removing paragraphs, or AI processing. Existing content versions, deduplication, UTF-16 positions, search, and recovery use the resulting representation.
- [Import preparation](../../crates/core/src/storage.rs) reports a normalizing phase that also includes hashing, sparse-index preparation, staging writes, and file synchronization. The phase label does not identify the slow operation. Actual timings have not been measured during this planning review.
- Import completion triggers shelf refresh. [Shelf chapter loading](../../src/application/shelf.ts) requests TOCs; on cache miss, the production path calls [build_toc](../../crates/core/src/m1_txt.rs), which repeatedly constructs/scans full-text character boundaries for chapter locators. This creates work proportional to text length times the number of detected chapters. It occurs after import publication or on initial TOC access, separately from the normalizing phase.
- Automatic decoding can fail with instructions to choose an encoding, but initial import currently accepts only a path; the existing manual encoding action requires an imported book. Failed-import recovery needs an actionable path.
- [ReaderView](../../src/components/Reader/ReaderView.tsx) already fills the window, but permanently reserves 80 px above and 128 px below the reading region, plus header/footer metadata. Hiding toolbars leaves this space reserved. Its top actions are bookmarks/search/save; bottom actions are contents/typography/theme/add bookmark. Encoding exists inside settings; configurable directory rules and automatic turning are missing.

### Reference boundary

PixNovel was inspected at revision `db2f9be`. Its phase 4, 6, and 7 plans and `src/views/ReaderView.vue`, `src/reader-panels.ts`, and `src/components/ChapterMatch.vue` provide reference behavior for immersive controls, mutually exclusive panels, automatic reading, and rule preview/application. Its current reader includes an additional download action, which is outside the requested four bottom actions. Its More menu contains disabled placeholders, not delivered capabilities to copy.

PixNovel's chapter rules extract numbers from existing online chapter titles. GripRead needs to recognize TXT heading lines and construct a directory of text locations. Reuse the interaction pattern, not the online data model. PixNovel supplies no local TXT import/encoding implementation to transplant; use GripRead's existing retained-source and relocation contracts.

### Delivery order

1. **P0: Silent import and transient results.** File selection starts the job directly. Do not automatically open a progress, metadata, encoding, or confirmation dialog. Show compact activity through the import entry; details/cancellation are optional. Refresh the shelf after committed success without automatically opening a book. Propose a 3-second success notice and an 8-second failure notice, both manually dismissible; pointer/focus interaction pauses dismissal. Preserve the latest failure details and retry through the import entry after its notice disappears. Picker cancellation is silent. Notification dismissal never cancels work or erases its authoritative terminal result.
2. **P0: Import-to-reading performance.** Measure file reading, detection/decoding, newline conversion, hashing/indexing, staging synchronization, commit, shelf refresh, TOC generation, and first readable render separately. Remove per-chapter full-text scans from TOC construction and deduplicate concurrent requests for the same book/version/rule. Keep chapter metadata independent of shelf usability and first-page rendering. Optimize repeated copies/passes in import preparation according to measurements; keep essential representation conversion and existing crash recovery. Decide on streaming only if measured large-file memory or time warrants it.
3. **P1: Viewport and toolbar shell.** Replace permanent toolbar-sized padding with compact, explicit reading insets and safe areas. Keep desktop line length readable without a vertically inset page card. Open with toolbars hidden; a center tap toggles them, while dragging or selecting text does not. Top right, in order: Directory rules, Encoding, More. Bottom, in order: Search, Automatic page turning, Contents, Settings. Keep the back action and book title at the top. Controls overlay the stable page geometry; revealing, hiding, or switching panels must not repaginate or change the saved passage. Move bookmark list/add and manual progress save into More; theme/typography remain under Settings.
4. **P1: Directory rules and tool integration.** Provide automatic recognition, built-in heading presets, and a per-book custom Rust regex with preview, apply, and restore-default actions. Preview shows matched titles and locations without changing the saved rule. Invalid rules retain the active directory and report the problem inline. Zero matches offer full-text navigation. Applying a rule rebuilds directory metadata without rewriting text or changing book identity/content version. Expose existing automatic/manual encoding choices through the top action; retain source re-association, cancellation, rollback, and verified position/bookmark relocation. Reuse existing search and contents behavior through the new bottom actions.
5. **P1: Automatic turning and integrated acceptance.** Start with PixNovel's paginated default of 8 seconds per page and an adjustable interval. Persist the chosen interval, but never resume running automatically after reopening. Use the existing reader controller and page effects, including instant rendering under reduced motion. Normal page turns may load the next content window: await completion, restart the interval, and continue. Pause on manual reading interaction, opening controls/panels, selection, blur/background, content replacement, reflow, encoding changes, navigation failure, or the end of the book. Resume only explicitly; never replay accumulated background time or queue overlapping turns. Finish with the checks and visual review below.

## Interfaces

Keep job ownership in the application layer and conversion/storage work in Rust. Separate notification identity and dismissal from import operation state so an old timeout or repeated terminal event cannot hide a newer operation's notice. The current import command can remain unchanged for normal imports; failed-import recovery may add an optional explicit encoding choice, defaulting to automatic detection. Update Rust declarations, generated bindings, the IPC adapter, service contracts, and consumers together if that request changes. A malformed or unsupported file must not become a misleading successful import.

Reader owns directory rule validation, preview, application, and TOC creation. Introduce a book-scoped persisted rule/revision and key TOC caches by content version plus rule revision. Include [ShelfStore](../../src/application/shelf.ts), whose current cache only tracks content version, in invalidation. Applying a rule refreshes shelf chapter labels and open reader contents together; stale previews/builds cannot replace newer choices. Heading detection preserves document order and existing UTF-16 positions. A rule edit alone leaves bookmarks/search positions valid; encoding changes continue to use the established content-version and relocation mechanism.

Reader preferences own the automatic-turn interval; the active timer and pause state belong to the reader session, outside page components. Use one panel state with focus restoration for Settings, Search, Contents, Rules, Encoding, More, and automatic-turn setup. Views render state and dispatch actions; they do not implement regex scanning or a second page-navigation engine.

Allowed implementation areas are `src/application`, `src/components/Bookshelf`, `src/components/Reader`, `src/reader`, `src/services`, generated types, relevant style tokens, Rust TXT/storage/command/model modules, their existing verification areas, and owning `.ai` documentation. Establish shared contracts and a decision record before new persistence or IPC changes. If implementation runs in parallel, separate import/notification, reader presentation, and Rust rule/performance ownership; shared storage/models/contracts changes need one integration owner. Review the combined result before committing.

## Acceptance criteria

- A normal import needs only a file choice. The user can keep using the shelf or reader while it runs. Success updates the shelf once; duplicates reuse the existing identity. Success and failure notices expire, manual dismissal works, and later events/timeouts do not resurrect old notices or dismiss new ones. Cancelling the picker shows no failure.
- A failed automatic decode offers an optional explicit-encoding retry without adding steps to successful imports. Failure and cancellation leave no apparently readable partial asset. Existing import/re-decode recovery and source-byte retention remain intact.
- Record cold and warm runs for deterministic 1, 10, and 50 MiB TXT fixtures, including UTF-8/GB18030/UTF-16, mixed line endings, non-BMP characters, and dense chapter headings. Compare import-commit, first-readable-page, metadata-ready time, and peak memory independently. Include duplicate import and uncached TOC cases. Set device-specific time budgets from the baseline before optimization, report before/after results, and verify TOC work no longer scales as a full-book scan per chapter. No performance improvement is claimed from the progress label alone.
- Desktop and phone-sized viewports have no permanent 80/128 px toolbar reservation. Review measured insets and rendered pages, including safe areas and small heights. Toolbar/panel toggles leave page boundaries and reading position unchanged; genuine viewport or typography changes reflow from the same locator without missing or repeated text.
- The three top-right actions and four bottom actions have the specified order and working behavior. Additional working actions remain reachable from More or Settings. Escape/back dismissal and focus restoration work without triggering a page turn; controls do not intercept text selection.
- Rules support Chinese/English/numeric heading fixtures, custom matches, invalid regex, no matches, preview cancellation, per-book persistence, rapid edits, restart, and stale-result rejection. Applying a directory rule changes no body text or saved reading location. Encoding changes update rule-derived metadata for the resulting content version.
- Search retains cancellation, result highlighting, and explicit empty/error states. Automatic turning crosses content windows with no duplicate/skipped pages, pauses under each defined condition, and stops at the final page. Position saves and normal exit still retain the latest passage.

## Implementation status

Silent import now separates application-owned work and durable terminal outcomes from expiring notices. Failure details and explicit-encoding retry remain available through the existing shelf import action; no permanent corner notification remains. Normalizing still includes the existing representation conversion, indexing, and file publication work.

TOC generation uses one forward line scan with bounded locator context. Concurrent requests for the same book, content version, and rule revision share a build. Cache reads, publication, and returned results validate their source snapshots; callers retry after a rule/content change. Cached directories retain verified content indexes, and the shelf invalidates old rule-derived labels even when text versions are unchanged. Schema 8 preserves existing books and locations while adding per-book rules; old preference JSON defaults the automatic-turn interval to 8 seconds.

The reader opens with hidden controls over a full-height measured page and uses the requested tool order. Rule previews and mutations have separate lifetimes: closing a panel cancels stale preview publication while accepted saves complete, report failure, and participate in exit retry. Automatic turning serializes pending navigation across pause/resume, pauses and drains before native exit, and never resumes after reopening. The React lifecycle adapter lives beside the reader view; the reading core remains independent of React.

### Performance evidence

Optimized standalone builds of production Storage modules compare baseline commit `4ed28de` with the reviewed implementation on deterministic 1, 10, and 50 MiB TXT files. Each MiB contains 64 chapter headings; fixtures cover UTF-8, GB18030, UTF-16LE, alternating LF/CRLF/CR, and non-BMP characters. Measurements include committed import, the first bounded content read, uncached/cached TOC, duplicate import, storage reopen, and whole-process peak RSS. All nine current encoding/size combinations preserved content reads, heading counts, duplicate identity, and TOC cache equality.

For 10 MiB UTF-8, committed import remained approximately 85–87 ms while uncached TOC fell from 5063 ms to 14 ms. The second cached TOC read after reopening fell from 26 ms to less than 1 ms. Current 50 MiB committed imports took approximately 389 ms for UTF-8, 2253 ms for GB18030, and 420 ms for UTF-16LE; uncached TOCs took 75–96 ms. The baseline 50 MiB UTF-8 import committed successfully but directory construction exceeded the 15-second process budget. The algorithm-only optimized comparison likewise showed 50 MiB directory generation taking approximately 34 ms without per-chapter full-book scans.

These are local review measurements with warm filesystem caches, source snapshots, and concurrent checks, not device-wide service-level promises. They exclude IPC, the system picker, and first rendered-page latency; Normalizing internals remain grouped. They demonstrate a directory improvement and do not establish faster import normalization. No pre-optimization latency budget or cold-disk result is claimed.

Desktop and phone-sized screenshot review confirms the requested toolbar order and full-height pages. Measured text height increased from 497 to 788 px at the desktop viewport and from 457 to 748 px at the phone-sized viewport, with the existing widths retained. Revealing toolbars preserves page start/end positions. The native tests exercise real IPC and rendered controls; automated import path selection does not establish new system-picker evidence.
