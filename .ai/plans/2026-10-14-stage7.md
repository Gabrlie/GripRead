# Stage 7: Builds, updates, EPUB, and server follow-up

Status: in-progress

## Outcome

Release 0.2.1. Each item below is a batch, committed and pushed to `dev` separately:

1. Every release carries Android APKs for each ABI plus a universal one, macOS apps for Apple Silicon and Intel, and a release page with the changes and download guidance ([workflow](../engineering/workflow.md#versions-and-releases)).
2. The app finds, downloads, and installs new versions from GitHub, or through the user's server while connected.
3. DRM-free reflowable EPUB books import and read like TXT books, with illustrations ([Reader](../subsystems/reader.md), [Library](../subsystems/library.md)).
4. The server refreshes online books on a schedule, caches new chapters, and serves them to connected devices ([Server](../subsystems/server.md)).

After the fourth batch, the user reads with 0.2.1 for a while before a fix round.

## Scope

**Included:** the four batches above.

**Excluded:**
- Windows and Linux builds;
- signing for macOS Gatekeeper;
- RSS, which is the next stage;
- EPUB styling beyond paragraphs, headings, and images.

## Interfaces

**Batch 1:**
- `scripts/android.mjs` passes bindgen arguments for all four Android targets.
- `build.gradle.kts` gives each ABI's APK the versionCode `run × 10 + ABI digit`.
- `src-tauri/tauri.macos.conf.json` enables the macOS bundle and updater archives; the updater key reaches CI as a secret.
- `scripts/release.mjs` writes the release page and `latest.json`, and the [changelog](../../CHANGELOG.md) supplies the highlights.

**Batch 2:** [Updates](../subsystems/updates.md) owns the behavior.
- `crates/core/src/update.rs` provides the commands and the server's cache.
- `Platform::update_target`, `install_apk` and `install_desktop_update` are implemented by `UpdatePlugin.kt` on Android and `tauri-plugin-updater` on macOS.
- The server exposes `/api/update/releases` and `/api/update/asset/{tag}/{name}`.
- On the frontend, `UpdateService`, the 关于 page and the startup prompt use them.

**Batch 3:** EPUB books follow the [EPUB-as-text decision](../notes/implemented/2026-10-14-epub-as-text.md).
- `crates/core/src/epub.rs` converts a book, and `txt::decode_source` is shared by every rebuild from source.
- Assets of kind `epub` keep their extras in schema 21 `epub_assets`.
- New commands: `list_book_images` and `read_book_image`.
- On the frontend, `src/reader/images.ts` holds the shared image registry for the renderer.

**Batch 4:** see the [server chapters decision](../notes/implemented/2026-10-14-server-chapters.md).
- `crates/server/src/jobs.rs` provides the schedule (`/api/jobs`), updates (`/api/jobs/update`) and chapters (`/api/sync/chapter`).
- New `chapters:online:<key>` sync records carry chapter lists.
- `SyncClient::update_shelf` and `fetch_chapter` are the device's calls to the server.
- `ChapterRelay` on storage puts the server ahead of the source.
- On the web version, 服务器账号 › 定时追更 sets the schedule.

## Acceptance criteria

- **Batch 1:**
  - Pushes run only the checks; `pnpm android:release` builds a signed APK locally for testing.
  - Pushing a `v0.2.1-beta.N` tag publishes a pre-release with the five APKs, the two macOS disk images, the updater archives, `latest.json`, and `SHA256SUMS`.
  - Its page shows the `Unreleased` changelog, the commits since the previous pre-release grouped by type, a download table, the image lines, and a compare link.

## Verification

**Batch 1:**
- `pnpm check` with the release-page tests.
- A local debug build of all four Android ABIs with `--split-per-abi` produced one library per APK and versionCodes ending in 1–4.

## Fix round

The user's first device test (against a 0.2.0 server) found nineteen items. All but one are fixed on `dev`, listed in the changelog's `Unreleased` section. The fixes cover:
- **Server and sync robustness:** an older server's page kept as chapter text, quiet fallback when the server lacks routes, background connection aborts, connection reuse and fewer cover uploads, the kept sign-in, and a new server's defaults overwriting a device's settings on first contact.
- **Shelf:** refresh without flicker, the 自动更新 schedule, 连载 counted only from real growth (schema 22 clears the old marks), 读完 at the last chapter, and the cloud count.
- **Backups:** the WebDAV account in kept backup files, and switches not dirtying the account form.
- **Web and server:** the web version without 备份与云端; server log entries with an area filter; 云书架 and 服务器管理 through the connected server; links on 关于.

The phone layout on the web version could not be reproduced: at phone width, the shelf, settings, and reader all render the phone layout. It waits for the user's details.

## Fix round 2

The second device test, against a server built from `dev`, found ten items, all fixed on `dev`:
- **Reader:** the curl's end no longer stutters near a chapter's end, since the next chapter is read and laid out after the turn and the curl reuses its canvases; 云端进度 shows both chapters and their gap.
- **Shelf:** a rubber-band pull-down that follows the finger and springs back, swiping sideways between groups, and 最近阅读或更新 ordering by the later of reading and new chapters.
- **Sources:** 按结果启用或禁用 also enables a disabled source that passes its check.
- **Server:** one 服务器 page (connection, 同步内容, 通过服务器更新书籍, the server's own settings); management errors show their message, inline where a section fails to load, and go to the log.

## Fix round 3

The user tested `v0.2.1-beta.1` and found seventeen items, all fixed on `dev`:
- **Updates:**
  - The download deleted its own verified file before renaming it, so every install failed and fell back to GitHub, which failed the same way. It now renames first.
  - 下载方式 (自动, 直连, 代理, 加速器 with a URL template, 服务器) picks the route.
  - Only automatic checks count toward the daily prompt, which also runs on returning to the app.
  - Release assets are renamed and ordered by platform.
- **Links:** the opener had no URL scope (`opener:allow-default-urls`).
- **Shelf:**
  - A sliding pager over the whole screen, clipped sideways.
  - The shown group is no longer synced.
  - The pull-down holds the page while pulling.
  - In server mode, 自动更新 only syncs, and quiet runs toast only new chapters.
- **Sync:** rounds run on events. There is no long poll, reading does not start rounds, there is a 5-minute timer while reading, and an outage logs once.
- **Server:** 定时追更 lists failed books. Devices record and clear each book's server-reported error.
- **Smaller items:**
  - replace and chapter rule import from an address, a file, or the clipboard;
  - deleting recovery points;
  - the brightness bar follows the system's live brightness.

## Handoff

The user re-tests a local release APK. Afterwards a `v0.2.1-beta.1` tag runs the full GitHub release once, and fixes precede the 0.2.1 release.
